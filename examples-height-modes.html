HM01 · Interactive Demo

Toggle between Container mode (grid caps itself with a pixel max-height and scrolls internally) and Full Height mode (grid sizes to its full content — the surrounding layout grows to fit).

Mode:
Container mode
Grid uses max-height. It grows with content up to the limit, then scrolls internally.
<web-grid style="max-height: 350px">
Full-height mode
Grid uses height: 100% against an unbounded parent — the percentage falls back to auto, so the grid sizes to its content and the outer layout expands to wrap it. The demo also sets isTableBorderOnly = true, which turns the outer .wg into a non-scrolling container so wheel events pass through to the page instead of being captured by the grid.
<web-grid style="height: 100%">
grid.isTableBorderOnly = true
Demo area
When to use which?
  • Container — default for most pages. Grid flows with the document, shrinks when data is short, and never grows beyond the pixel cap. Page scrolls around it.
  • Full Height — when you want every row visible without an internal scrollbar. The grid expands to its natural height and the page scrolls instead.

HM02 · How sizing works internally

The shadow DOM scroll container uses max-height: inherit, so a max-height set on the host element propagates inside. That's the whole mechanism for Container mode — set a pixel cap and the grid scrolls internally.

/* Inside the grid's shadow DOM */
.wg {
  max-height: inherit;  /* picks up host max-height */
  overflow: auto;       /* single scroll container */
}

In Full Height mode there is no cap — height: 100% resolves to auto against the unbounded parent, the grid sizes to its content, and the outer layout grows with it. Sticky headers still work in Container mode thanks to the single scroll container.
