### 2. Move `--wg-tree-chevron-*` declarations into variables.css

**Check:** C-BV-3 — `:host` declares every component-local variable
**File:** `packages/web-grid/src/css/tree.css:10-15`
**Why this matters:** Variable declarations distributed across
feature files break the "one place for `--wg-*`" contract — consumers
can no longer find all overrides by inspecting `:host` in DevTools or
by reading `variables.css`. Also violates CLAUDE.md invariant #6.
**Patch:**
```diff
- /* tree.css lines 10-15 */
- :host {
-   --wg-tree-indent: 1.25rem;             /* per-level indent */
-   --wg-tree-chevron-size: 1rem;          /* chevron width/height (also used for leaf spacer) */
-   --wg-tree-chevron-color: var(--wg-text-color-2);
-   --wg-tree-chevron-gap: 4px;            /* gap between chevron and content */
- }
```
Insert the four declarations into the existing `:host` block in
`packages/web-grid/src/css/variables.css` (suggest a new
`/* === TREE === */` section banner before the row-locking block).

### 3. Wrap `#fff` in `light-dark()` and fix non-canonical `--base-*` read

**Check:** C-CS-2 — light-dark() in color fallbacks (plus a non-canonical
`--base-text-inverted` read flagged in taxonomy alignment)
**File:** `packages/web-grid/src/css/variables.css:378`
**Why this matters:** Bare `#fff` doesn't auto-flip when
`color-scheme` resolves to dark — the contract is that every color
fallback in variables.css resolves through `light-dark(<light>,
<dark>)`. Also, `--base-text-inverted` isn't in the canonical
`--base-*` taxonomy; the correct read is `--base-text-color-on-accent`.
**Patch:**
```diff
- --wg-selection-row-number-color: var(--base-text-inverted, #fff);
+ --wg-selection-row-number-color: var(--base-text-color-on-accent, light-dark(#fff, #fff));
```
(White-on-accent reads correctly in both light and dark modes because
the accent is the same color in both, so the `light-dark()` pair is
intentionally identical here — but the wrapping makes it
script-conformant and consistent with `--ms-text-color-on-accent` in
web-multiselect.)

### 9. Decide `tryHandle*` rename or document

**Check:** C-NC-9 — internal handler methods use handle* prefix
**File:** `packages/web-grid/src/modules/actions/adapter.ts` lines
161, 412, 449, 746, 800
**Why this matters:** Canonical naming is `handle*` for internal
DOM handlers. The `try*` prefix is unconventional but signals a
boolean return contract.
**Recommended:** Add a `VALIDATION-NOTES.md` entry — `tryHandle*` is
the pipeline-dispatch idiom:
```markdown
## C-NC-9 — Action-pipeline tryHandle* idiom
The `ActionPipelineAdapter` uses `tryHandle*` (e.g. `tryHandleKeyDown`,
`tryHandleClick`) for its 5 dispatch entrypoints in
`src/modules/actions/adapter.ts:161, 412, 449, 746, 800`. The `try`
prefix signals the boolean return contract: `true` = the action
pipeline owned the event (skip legacy path), `false` = pass through
to the legacy handler. The 4 call sites in
`src/web-component.ts:1900, 1942, 1996, 2081` are written as
`if (this.pipelineAdapter?.tryHandleX(e)) { ... }` — the boolean
return is load-bearing. Renaming to `handleX` would lose the
visual cue that the return value matters.
```

### 11. Decide on mixed `on*` vs `*Callback` naming

**Check:** C-NC-4 — notification callbacks match host shape
**Files:** `packages/web-grid/src/types.ts` — `onselect` (76),
`onclick` (318, 327, 381, 416), `onfilterchange` (509), plus README
references to `onpaste`, `onbeforepaste`, `ondatarequest`, `onsort`.
**Why this matters:** The web-component host expects `*Callback`
for notifications; `on*` is the Svelte / native-event shape. The
grid mixes both — `validateCallback` / `beforeCommitCallback` /
`renderCallback` use the canonical shape while `onpaste` / `onsort`
don't.
**Audit needed:** For each `on*` field, decide:
- HTML-event-like (`onclick` on action items, `onfilterchange` on
  the grid host) — defensible parallel to native event handlers;
  document the choice in `VALIDATION-NOTES.md` rather than renaming.
- Business-injection (`onpaste`, `onbeforepaste`, `onsort`,
  `ondatarequest`) — rename to `pasteCallback`, `beforePasteCallback`,
  `sortCallback`, `dataRequestCallback` to match canonical shape.

Each rename is a public-API break — bundle with the C-NC-3 / C-NC-6
renames into a single migration version with a thorough CHANGELOG
migration table.
