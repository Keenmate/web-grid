entries in "Fixes to apply" below may turn out to be **false

runs, any flag covered by a matching entry is downgraded from
❌ Fail to ✅ Pass / ⚠️ Exception and **omitted from this section**
— so it doesn't re-surface every run.

Before treating an entry below as a developer task:

1. Read the patch — does the fix actually apply to *this* component?
2. If yes → do the fix.

Deferrals ("we'll fix this later", "low priority", "out of scope")
are **NOT valid `VALIDATION-NOTES.md` entries** — they get

### 2. Add the unlayered-reset footgun warning to `docs/theming.md`

**Check:** C-CSS-10 — layer contract documented (must include the unlayered-reset warning)
**File:** `packages/web-grid/docs/theming.md:223-267` (Cascade-layer contract section)
**Why this matters:** web-grid ships `@layer component` rules. A
consumer-side universal reset (`* { margin: 0; padding: 0 }` — common
in Bootstrap reboot, Tailwind preflight, hand-rolled normalize.css)
is unlayered and beats every rule in `@layer component`, causing the
grid to render with collapsed padding / wrong box-sizing despite
variables resolving correctly. The svelte-treeview showcase ate this
bug in 2026-06. The current "Cascade-layer contract" section
explains layer order and the override path but doesn't warn about
the inverse — the unintended reset interaction.
**Patch:** Add a new subsection after "Why this matters"
(`docs/theming.md:267`):

```markdown
### The unlayered-reset footgun

The same rule that gives consumers a clean override path —
*unlayered beats layered* — bites in the other direction when a
consumer ships a universal reset *outside* any layer:

```css
/* Consumer's global stylesheet — Bootstrap reboot, Tailwind preflight, etc. */
* { margin: 0; padding: 0; box-sizing: border-box; }
```

Per the CSS `@layer` specification, that `*` rule is **unlayered**,
so it beats *every* rule in web-grid's `@layer component` regardless
of specificity. The grid's `.wg__cell { padding: var(--wg-cell-padding) }`
loses to `* { padding: 0 }`, and the table renders with collapsed
spacing even though all the `--wg-*` variables resolved correctly.

**Fix on the consumer side:** wrap universal resets in a named
layer so they're outranked by web-grid's layered defaults:

```css
@layer reset, page;

@layer reset {
  * { margin: 0; padding: 0; box-sizing: border-box; }
}

/* Intentional overrides stay unlayered — they still beat web-grid's defaults */
.my-app-header { padding: 1rem; }
```

This is the first thing to check if the grid renders with collapsed
padding, missing margins, or wrong box-sizing despite the variables
resolving to sane values.
```

### 3. Move 5 boolean Config fields to the `is*` / `should*` prefix

**Check:** C-NC-3 — boolean Config/Props fields use `is*` / `should*` / `has*` / `can*`
**File:** `packages/web-grid/src/types.ts` (the `QuickGridProps<T>` interface, lines 497–660)
**Why this matters:** Consumers can't tell at a glance whether a
Config field is a flag or a value when the boolean uses neither the
prefix convention nor a domain-meaningful name. The script
flagged 2; an eyes-on read of `QuickGridProps<T>` shows 5 actual
violations (the script's regex misses `boolean | 'auto'` and
`boolean | ((row) => boolean)` unions, which contain the bare
boolean variant).
**Patch — rename + add deprecated aliases for one release:**

```diff
- showPagination?: boolean | 'auto'  // true=always show, false=never, 'auto'=hide when ≤1 page
+ isPaginationVisible?: boolean | 'auto'  // true=always show, false=never, 'auto'=hide when ≤1 page

- toolbarFollowsCursor?: boolean  // Toolbar follows mouse cursor horizontally (default: false)
+ shouldToolbarFollowCursor?: boolean  // Toolbar follows mouse cursor horizontally (default: false)

- tableBorderOnly?: boolean            // Border only around table, not pagination/toolbar (default: false)
+ isTableBorderOnly?: boolean            // Border only around table, not pagination/toolbar (default: false)
```

The other two flagged ones (`nowrap` line 179, `multiple` line 114)
sit on data-model interfaces (column / editor config), which
correspond to HTML `<col>` / `<select multiple>` conventions and are
**exempt** from the `is*` prefix rule per C-NC-3's data-model
exception. No change needed there — but the exemption deserves a
short note in `VALIDATION-NOTES.md` so future runs stop counting
those two against the score (see Step 9a follow-up).

### 4. Rename or alias 9 `*Type` / `*Info` types

**Check:** C-CST-8 / C-NC-11 — TS interface suffixes match the closed set
**Files:**
- `packages/web-grid/src/types.ts:6,275,340,367,404,786`
- `packages/web-grid/src/modules/click-events/index.ts:7`
- `packages/web-grid/src/modules/focus-events/index.ts:7`
- `packages/web-grid/src/modules/datepicker/types.ts:53`

**Why this matters:** The closed-set TS suffix policy in
`component-structure.md` forbids `Type` / `Info` / `Data` / `Object`
/ `Model` suffixes. Vocabulary drift makes consumers reach for the
wrong type. The two patterns flagged here:

| Pattern | Examples | Fix |
|---|---|---|
| String-literal union with `Type` suffix | `EditorType`, `ClickEventType`, `FocusEventType`, `PredefinedToolbarItemType`, `RowActionType`, `PredefinedContextMenuItemType`, `PredefinedHeaderMenuItemType` | Drop the suffix — `Editor` / `ClickEvent` / `FocusEvent` / `PredefinedToolbarItem` / `RowAction` / `PredefinedContextMenuItem` / `PredefinedHeaderMenuItem`. Each is the name of the enum-like concept, not a "type" in the TS sense. |
| Data-model with `Info` suffix | `RowLockInfo`, `FormatInfo` | Drop the suffix — `RowLock` / `Format`. Both describe one item, plain data-model. |

**Patch (representative — apply the same shape to each):**

```diff
- export type EditorType = "text" | "number" | "checkbox" | "select" | "combobox" | "date" | "autocomplete" | "custom"
+ export type Editor = "text" | "number" | "checkbox" | "select" | "combobox" | "date" | "autocomplete" | "custom"
+ /** @deprecated use `Editor` */
+ export type EditorType = Editor
```

Keep deprecated aliases for one minor version so external consumers
don't break. Drop the aliases in the next major.

### 5. Document the `*Member`-only data-extractor stance (D-NC-7 = C)

**Check:** C-NC-6 — data extractors use `get*Callback` + `*Member` pair
**Files:** `packages/web-grid/src/grid.ts:317-320,1279-1300` plus the
five member declarations exposed on the WebGrid class
(`idMember`, `lockedMember`, `treeLevelMember`, `treeParentMember`,
`treePathMember`) and `packages/web-grid/src/types.ts:213` (`tooltipMember`).

**Why this matters:** Six `*Member` fields exist with no paired
`get*Callback` — the script reads this as an asymmetric data-
extractor surface. In web-grid these are deliberately
**member-only**: the values are property names on the row data, and
the grid doesn't currently support computed alternatives for tree
identity / locking / tooltip text. That's a legitimate D-NC-7 = C
choice (member-only), but it isn't documented anywhere, so the
script re-promotes the absence to a Fail every run.

**Patch — document in `VALIDATION-NOTES.md` (see Step 9a):**

```markdown
## C-NC-6 / D-NC-7 = C — Member-only data extractors

Six `*Member` fields (`idMember`, `lockedMember`, `tooltipMember`,
`treeLevelMember`, `treeParentMember`, `treePathMember`) are
intentionally member-only — they read a property name off the row
data. No `get*Callback` pairs because:

- Tree identity / locking / row-tooltip text are 1:1 with a row
  property in every consumer scenario the grid has seen; a function
  override would be ceremony with no use case.
- Adding a `getIdCallback` / `getLockedCallback` etc. would double
  the public surface (12 fields instead of 6) for a feature nobody
  asked for.

If a real use case appears (computed tree paths, derived row
identity, formatted tooltip text), add the matching
`get*Callback` field then — the design isn't closed, just
intentionally lean. Matches D-NC-7 = C in
`naming-conventions.decisions.md`.
```

### 6. Move tooltip / dropdown / virtual-scroll state out of the Element class

**Check:** C-CST-6 — Element layer holds no business state
**File:** `packages/web-grid/src/web-component.ts:227-326` (GridElement
class declaration; specifically the ~30 instance fields covering
tooltip lifecycle, dropdown state, virtual scroll bookkeeping, and
toolbar hover tracking).

**Why this matters:** The Element class is supposed to be a thin
I/O wrapper that holds a Logic class instance and lifecycle plumbing
(AbortController, MutationObserver). web-grid's GridElement holds
substantial UI state:

- Tooltip state: `tooltipElement`, `tooltipArrowElement`,
  `tooltipAnchor`, `tooltipShowTimer`, `tooltipHideTimer`,
  `_tooltipShowDelay`, `_tooltipHideDelay`.
- Dropdown state: `dropdownOpen`, `dropdownOptions`,
  `highlightedIndex`, `filterText`, `isUserFiltering`,
  `justSelected`, `isOpeningDropdown`, `dropdownUserInteracted`,
  `isClosingViaToggle`.
- Virtual scroll: `virtualScrollStart`, `virtualScrollEnd`,
  `isLoadingMoreItems`, `isProgrammaticScroll`.
- Toolbar hover: `toolbarHideTimeout`, `toolbarHovered`,
  `toolbarMoveInProgress`, `hoveredCell`, `currentCellToolbarItems`,
  `toolbarMousemoveHandler`, `toolbarShortcutHandler`.
- Autocomplete async: `searchDebounceTimer`, `searchAbortController`,
  `isSearching`.

The `modules/tooltip/`, `modules/dropdown/`, `modules/scroll/`,
`modules/toolbar/` directories already exist as the right home for
that state — they're partially extracted but each module pulls
state from `ctx` (the GridElement) rather than owning it.

**Patch:** Move each cluster of state into a dedicated Service
class living next to its module:

- `modules/tooltip/TooltipService.ts` owns the 7 tooltip fields,
  exposes `show(anchor, content)` / `hide()`.
- `modules/dropdown/DropdownService.ts` owns the 9 dropdown fields,
  exposes `open()` / `close()` / `commit()` etc.
- `modules/scroll/VirtualScrollService.ts` owns the 4 vscroll
  fields.
- `modules/toolbar/ToolbarService.ts` owns the 7 toolbar fields.
- `modules/dropdown/AutocompleteService.ts` (or merge into Dropdown)
  owns the 3 autocomplete fields.

GridElement keeps only `grid` (the Logic instance), `shadow`,
`styleElement`, `customStyleElement`, `updatePending`, and the four
EventManager instances (`scrollEvents`, `focusEvents`, `clickEvents`,
plus any new one).

This is a substantial refactor — staged across multiple PRs is
fine. The score impact is one check (C-CST-6) but the architectural
benefit is real: Element shrinks from ~5000 lines to ~1000, the
Logic class regains exclusive ownership of state, and each Service
can be unit-tested independently.

**Alternative if refactor is deferred:** add a
`VALIDATION-NOTES.md` entry documenting why the state cluster
remains on GridElement *as the correct architectural choice* —
not "we'll fix this later". The current code organization
arguably reflects a different decomposition (state lives where the
DOM listener that owns it lives, with `modules/*` as algorithm
namespaces, not Service classes). If that *is* the team's chosen
architecture, document it; the auto-script can't tell the
difference between a deferred refactor and a deliberate decomposition,
and only the team can make that call.

### 7. Migrate `--base-tooltip-color` reads to `--base-tooltip-text-color`

**Check:** Canonical taxonomy alignment (informational, not a numbered check)
**File:** `packages/web-grid/src/css/variables.css` — search for
`var(--base-tooltip-color`.

**Why this matters:** The canonical `--base-*` taxonomy renamed
`--base-tooltip-color` to `--base-tooltip-text-color` on 2026-06-11
(matching `--base-text-color-on-accent` and the `*-text-color`
naming pattern). Components were allowed to keep the legacy name
as a deprecated alias for one release. We're inside that window;
the migration is now safe to do.

**Patch:**

```diff
- --wg-tooltip-color: var(--base-tooltip-color, light-dark(#ffffff, #1a1a1a));
+ --wg-tooltip-color: var(--base-tooltip-text-color, var(--base-tooltip-color, light-dark(#ffffff, #1a1a1a)));
```

The double chain — read the new name first, fall back to the legacy
name, then the literal — keeps consumers on the old name working
through this release. Drop the legacy read in the next major.
Update `component-variables.manifest.json` to swap the
`base-tooltip-color` entry for `base-tooltip-text-color`.
