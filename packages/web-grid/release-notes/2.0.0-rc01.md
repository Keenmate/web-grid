# Web Grid 2.0.0-rc01 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-grid@rc`)

These notes cover the changes since **1.2.0-rc02**, the last version on npm (the 1.3.0 – 1.5.1 theming work
was already folded into 1.2.0-rc02). They are the first release notes for this package; for earlier versions
read the [CHANGELOG](https://github.com/KeenMate/web-grid/blob/prod/CHANGELOG.md).

This is a **major release: breaking, with no aliases.** `<web-grid>` now builds on
`@keenmate/web-components-core`: every scalar option is a real HTML attribute and a validated, reactive input;
callbacks take one `ctx`; events are DOM events with `on*` twins; the row toolbar, the cell / header menus and
the shortcuts are core action items; names follow the suite-wide naming rules. On top of that the grid becomes
an ARIA grid with one tab stop, follows Excel for editing and clipboard (leaving a cell saves, copy = what the
cell shows, paste and typing in every edit mode), formats numbers by locale and gets a full `/locale` label
system. A `^1.x` range will not pull this version.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/KeenMate/web-grid/blob/prod/CHANGELOG.md) (section
2.0.0-rc01); this document is the upgrade guide and the highlights.

## Breaking changes

### Every option is an attribute and a validated input

1.x observed no attributes: `<web-grid is-striped>` was dead markup, every option worked only as a JS
property. The element is now a core `BlissElement`: every scalar / enum option is a row of one input table — an
HTML attribute, a typed property (`GridElementConfig`) and a validated value, reactive both ways. Booleans use
the short HTML form derived from the property name (`is*Enabled` → `enable-*`, `is*Shown` → `show-*`, `should*`
→ bare, `is*Allowed` → `allow-*`):

```html
<web-grid enable-paging page-size="25" striped hoverable
          preset="excel" edit-trigger="dblclick" sort-mode="single"></web-grid>
```

Structured data (`columns`, `items`) and the self-mutated UI state (`currentPage`, `sort`, `filters`,
`focusedRowIndex`, …) stay properties; the grid-level callbacks are property-only inputs (anything but a
function / `null` / `undefined` is refused). A property write reaches the grid on the coalesced flush; the
element's methods and `el.controller` flush first, so `el.pageSize = 25; el.totalPages` still reads the new
value. `preset` is a batch preset: an input set explicitly in the same tick or markup wins, whatever the order
(`<web-grid preset="excel" edit-trigger="click">` keeps `click`).

### Property renames

No aliases. The deprecated 1.x aliases `showPagination`, `tableBorderOnly`, `toolbarFollowsCursor`,
`toolbarAlign`, `toolbarTopPosition` are gone too.

### Validated inputs

One rule for attributes and properties, the same as every Keenmate component: an invalid value warns (through
the grid's logger), fires the core `input-rejected` event and keeps the previous value (it used to reach the
engine). Removing an attribute or assigning `undefined` resets the default.

- `pageSize` refuses `null` / `0` / `'abc'`; `preset` an unknown name.
- `pagination-position` / `summary-position`: `|`-separated `top-` / `bottom-` + `left` / `center` / `right`;
  `pagination-layout`: `|`-separated `first`, `previous`, `page-info`, `next`, `last`, `page-size` (an unknown
  part used to render nothing silently).
- `scroll-max-height`, `column-min-width`, `toolbarBtnMinWidth`: CSS lengths (a number = px:
  `el.scrollMaxHeight = 240` → `'240px'`); `cell-toolbar-offset` a number or a length.
- `expandLevel`: a whole number ≥ 0 or `null` (a negative number used to mean "all"); `isRowEditable`: a boolean
  or `null` / `undefined` — unset reads back `null` (was `undefined`).
- `readonly` / `disabled` follow the native presence rule and reflect: `readonly="false"` means read-only;
  `el.isReadonly = true` writes `readonly=""`, `false` removes it.

### Callbacks take one `ctx`

Every callback takes one `ctx` object. Every ctx and event detail carries `controller` (`el.controller`) and
`element` (the host), both non-enumerable (`JSON.stringify` sees only the data).

| 1.2 | 2.0 |
|---|---|
| `rowClassCallback(row, rowIndex)` | `getRowClassCallback({ row, rowIndex })` |
| `customStylesCallback()` | `getCustomStylesCallback(ctx)` |
| `paginationLabelsCallback(ctx)` / `summaryContentCallback(ctx)` / `shortcutsHelpContentCallback()` | `getPaginationLabelsCallback(ctx)` / `renderSummaryCallback(ctx)` / `renderShortcutsHelpCallback(ctx)` |
| `validationTooltipCallback(ctx)` (grid + column) | `getValidationTooltipCallback(ctx)` — the cell ctx + `error` |
| `treeChevronCallback({ expanded, … })` | `renderChevronCallback({ row, isExpanded, hasChildren, level, path })` |
| `isRowEditable: boolean \| (row) => boolean` | `isRowEditable: boolean` + `getIsRowEditableCallback({ row })` |
| `idValueCallback(row)` | `getIdCallback({ row })` |
| `createEmptyRowCallback()` / `createRowCallback(pastedData, rowIndex)` | `createEmptyRowCallback(ctx)` / `createRowCallback({ data, rowIndex })` |
| `rowLocking.isLockedCallback(row, i)` / `getLockInfoCallback(row, i)` / `canEditLockedCallback(row, lock)` | `getIsLockedCallback({ row, rowIndex })` / `getLockInfoCallback({ row, rowIndex })` / `getCanEditLockedCallback({ row, rowIndex, lockInfo })`; `lockTooltipCallback` (never called) removed |
| `fillDragCallback(detail)` → `false` | `beforeFillCallback(ctx)` → `false` cancels (async OK) |
| `onbeforepaste(detail)` + `detail.cancel = true` | `beforePasteCallback(ctx)` → `false` cancels (async OK) |
| `onfilterchange(filters)` set → server-side filtering | `filterMode: 'server'` (`filter-mode`) + the `filter-change` event |
| column `formatCallback(value, row)` | `getDisplayValueCallback(ctx)` — `{ row, rowIndex, column, colIndex, field, value }` |
| column `templateCallback(row)` | `renderCellCallback(ctx)` |
| column `cellClassCallback(value, row)` / `tooltipCallback(value, row)` | `getCellClassCallback(ctx)` / `getTooltipCallback(ctx)` |
| column `filter(filterValue, row)` | `filterCallback({ filterValue, row, column, field })` |
| column `isEditable: boolean \| (row) => boolean` | `isEditable: boolean` + `getIsEditableCallback({ row })` |
| column `beforeCommitCallback(ctx)`, deprecated `validateCallback(value, row)` | `validateCallback(ctx)` — same result contract; ctx gains `column`, `colIndex`, `source: 'edit' \| 'paste'` |
| column `cellEditCallback(ctx)` | `renderEditorCallback(ctx)` — the cell ctx + `commit` / `cancel` |
| column `beforeCopyCallback(value, row)` / `beforePasteCallback(value, row)` | `getCopyValueCallback(ctx)` / `getPasteValueCallback({ …cell, text })` |
| column `renderCallback` | removed (never called) |
| `editorOptions.getDisplayCallback` / `getSearchCallback` / `getDisabledCallback` `(option)` | `getDisplayValueCallback` / `getSearchValueCallback` / `getIsDisabledCallback({ option })` |
| `editorOptions.renderOptionCallback(option, ctx)` | `renderOptionCallback({ option, optionIndex, isFocused, isSelected, isDisabled })` |
| `editorOptions.searchCallback(query, row, signal)` | `searchCallback({ term, row, rowIndex, column, field, signal })` |
| `editorOptions.onselect(option, row)` | `editorOptions.onSelect({ option, row, rowIndex, column, field, … })` |

```js
// 1.2
column.formatCallback = (value, row) => `${value} ${row.currency}`;
// 2.0
column.getDisplayValueCallback = ({ value, row }) => `${value} ${row.currency}`;
```

### Events are DOM events with `on*` twins

The lowercase `on*` properties (which collided with native handlers: `onpaste`, `onselect`) are gone. Every
event is a real DOM event (bubbles, not composed) plus a camelCase `on<Name>` twin, called with the same detail
first.

| 1.2 | 2.0 event / twin |
|---|---|
| `onrowchange` | `row-change` / `onRowChange` |
| `onroweditstart` / `onroweditcancel` | `cell-edit-start` / `cell-edit-cancel` (`onCellEditStart` / `onCellEditCancel`) |
| `onvalidationerror` | `validation-error` / `onValidationError` — also from paste; detail gains `source` |
| `ontoolbarclick(detail)` | `action` / `onAction` — every toolbar, inline, cell-toolbar, menu and shortcut item (`source`: `row-toolbar` / `cell-toolbar` / `context-menu` / `header-menu` / `keyboard`; `event` → `sourceEvent`) |
| `onrowaction` | removed (never fired) |
| `ondatarequest` | `data-request` / `onDataRequest` — also after a header-menu sort |
| `onrowdelete` + the non-bubbling `rowdelete` event (a request) | `row-delete` / `onRowDelete` `{ rows, rowIndices }` — reports a deletion after the fact |
| `onrowfocus` `{ row, rowIndex, previousRowIndex }` | `focus-change` / `onFocusChange` `{ row, rowIndex, oldRowIndex }` |
| `oncellselectionchange` | `cell-selection-change` / `onCellSelectionChange` (gains `fields`, `rows`) |
| `onfilterchange` | `filter-change` / `onFilterChange({ filters })` |
| `oncolumnresize` / `oncolumnreorder` | `column-resize` / `column-reorder` (`onColumnResize` / `onColumnReorder`) |
| `onexpandedpathschange({ path, expanded })` | `row-expand` / `row-collapse` `{ row, path }` + `expanded-change { paths }` |
| `onrowlockchange` | `row-lock-change` / `onRowLockChange` — `rowIndex` is the display index (`-1` when not displayed) |
| paste completion | `cell-paste` / `onCellPaste` (`CellPasteEventDetail`) |
| `oncontextmenuopen(ctx)` / `onheadercontextmenuopen(ctx)` | `beforeContextMenuOpenCallback(ctx)` / `beforeHeaderMenuOpenCallback(ctx)` — `false` = no grid menu, an entries array = shown instead |

Every event fires once per gesture / API call and only when its state changed (re-selecting the same range is
silent).

### Toolbar, menus and shortcuts are core action items

The row toolbar, the cell-toolbar override, the cell / header context menus and `rowShortcuts` /
`rangeShortcuts` share one item shape (core `/actions`). Activation order: `beforeActionCallback` (`false`
cancels) → item `onClick` → the built-in → the `action` event (a notification after the fact).

| 1.2 | 2.0 |
|---|---|
| toolbar `{ id, icon, title, label, type, danger, disabled, hidden, tooltip: { description, shortcut }, tooltipCallback, onclick({ row, rowIndex }) }` | `{ action?, id?, icon, text, tooltip, shortcut, isDanger, isDisabled, isVisible, isToggled, cssClass, get*Callback(ctx), onClick(detail), isTextVisible }` — `text` is the accessible name + tooltip heading |
| toolbar `group: n` / menu `dividerBefore: true` | a divider entry `{ divider: true, text? }` (`createMenuDivider(text)`) |
| `cellToolbar(row, rowIndex, field, colIndex)` | `getCellToolbarItemsCallback(cellCtx)` — merged over `rowToolbar` by `id` / `action` |
| menu `{ id, label \| fn, icon \| fn, visible \| fn, disabled \| fn, danger, type, onclick(ctx) }` | `{ action?, id?, text, getTextCallback, icon, getIconCallback, isVisible, getIsVisibleCallback, isDisabled, getIsDisabledCallback, isDanger, isToggled, shortcut, onClick(detail), children, getChildrenCallback, shouldCloseOnClick }` |
| header `submenu(ctx)` (child `onclick` never ran) | `children` / `getChildrenCallback(ctx)` (sync or async); every child activates |
| header built-ins `'sortAsc' \| 'sortDesc' \| 'clearSort' \| 'hideColumn' \| 'freezeColumn' \| 'unfreezeColumn' \| 'columnVisibility'` | `'sort-asc' \| 'sort-desc' \| 'clear-sort' \| 'hide-column' \| 'freeze-column' \| 'unfreeze-column' \| 'column-visibility'` |
| toolbar built-ins `'moveUp' \| 'moveDown'` | `'move-up' \| 'move-down'` |
| a custom item whose `id` was a built-in name ran the built-in | built-ins only by `action`; `id` identifies custom items |
| `HeaderMenuContext.columnIndex` / `ContextMenuContext.cellValue` | `colIndex` / `value` (`CellContext`) |
| `rowShortcuts: [{ key, id, label, action(ctx), disabled }]` | `[{ shortcut, id?, action?, text, onClick(detail), isDisabled, getIsDisabledCallback }]` (`Mod` = ⌘ / Ctrl) |
| `data-toolbar-item` / `data-action-id` / `data-item-id` | `data-action` (built-in name or `custom`) + `data-id` |

Toggle state is `isToggled` / `getIsToggledCallback`; a toggled context-menu item is
`role="menuitemcheckbox"` + `aria-checked`.

```js
// 1.2
grid.rowToolbar = [{ id: 'archive', icon: '📦', title: 'Archive', onclick: ({ row }) => archive(row) }];
// 2.0
grid.rowToolbar = [{ id: 'archive', icon: '📦', text: 'Archive', onClick: ({ row }) => archive(row) }];
```

### Built-in row actions do the work

In 1.x `'add' | 'delete' | 'duplicate' | 'moveUp' | 'moveDown'` were icon presets and the page did the work in
`ontoolbarclick`. Now they act: `add` inserts `createEmptyRowCallback(ctx)`'s row (else a blank row) after the
row, `delete` removes it, `duplicate` inserts `createDuplicateRowCallback({ row })`'s copy (else a shallow copy
with the `idMember` field cleared), `move-up` / `move-down` swap with the displayed neighbour. They act on the
whole row selection when the clicked row is in it. Ctrl/Cmd+Delete runs `delete`; `row-delete` reports the
removal (programmatic `removeRows` / `removeRow` don't fire it). Veto any of them with `beforeActionCallback`
returning `false`. **Remove your own add / delete / move code, or the row changes twice.**

### `el.grid`, `WebGrid` and the internal members are gone

- `el.grid` (the internal `WebGrid` engine) → **`el.controller`**: a frozen facade over rows, drafts,
  validation, locking, selection, tree, columns, focus and menus; the same members on the element where they
  are element API. The engine class is no longer exported and not reachable as `el.engine` either.
- The module plumbing on the element is private: `shadow`, `dropdown`, `autocomplete`, `toolbar`,
  `filterRow`, `tooltip`, `datepicker`, `menu`, `virtualScroll`, `isCommittingFromKeyboard`,
  `isTransitioningCells`, `render()`, `getCurrentEditingColumn()`, `getCurrentEditorOptions()`,
  `moveFocusAfterCommit()`, `escapeHtml()`, … Use `el.shadowRoot` (open) for the shadow root. The documented
  calls stay: `scrollToRow()`, `openCustomEditor()`, `focusCell()`, `startEditing()`.

### Row identity: one `idMember`

### Context menus on core `/menu`

The cell and header menus are core `openMenu()` — rendered in the grid's shadow root.

- **Classes:** `.wg-context-menu-container` is gone; `.wg-context-menu` / `--submenu` / `__item`
  (`--disabled` / `--danger` / `--has-submenu`) / `__icon` / `__label` / `__shortcut` / `__divider` →
  `.km-menu` / `.km-menu--submenu` / `.km-menu__item…` / … ; scoping hooks `wg-context-menu` (cell menu),
  `wg-header-menu` (header menu); the column toggles are `wg-header-menu__column-toggle`.
- **Variables:** the `--wg-cm-*` set, `--wg-context-menu-min-width` / `-z-index` defaults and
  `--wg-z-context-menu` are removed. One public set `--wg-context-menu-*` themes both menus, unset by default
  (`--wg-context-menu-*` → `--km-menu-*` page-wide → `--base-*` → core default). Old → new:
  `--wg-cm-background` → `-bg`, `--wg-cm-hover-bg` → `-bg-hover`, `--wg-cm-text-danger` → `-danger-color`,

  `--wg-cm-icon-size` → `-icon-width`, `--wg-cm-icon-gap` → `-item-gap`, the rest by the same name.

### Icon strings go through core `renderIcon`

A toolbar / inline-action `icon`, `editButtonIcon` and the dropdown's option icon (`iconMember` /
`getIconCallback`, always escaped text in 1.x) are read like every Keenmate icon: markup (starts with `<`) as is
→ a core built-in name (`add`, `check`, `close`, `delete`, `edit`, `settings`, …) as a glyph masked from
`--base-icon-<name>` → the grid's `renderIconCallback` → the page-wide `window.components.renderIconCallback`
→ an icon-font class list as `<i class="wg__icon …" aria-hidden="true">` → anything else (an emoji, `✎`) as
escaped text. A plain word used to show as the word; a non-markup string with `<` / `&` used to be inserted as
HTML.

### Persisted column state

Persistence is core `createStateStore()`. `gridName` → `storage-key` / `storageKey` (unset = off);
`shouldPersistColumnWidths` / `shouldPersistColumnOrder` are inputs (`persist-column-widths` /
`persist-column-order`). The localStorage key is `km-state:web-grid:<storage-key>` (was
`wg-<gridName>-state`): **saved widths / orders are not carried over.** New `loadStateCallback` /
`saveStateCallback` keep the state where the page wants it (set both; either alone switches localStorage
off). Loading is asynchronous: saved widths / order apply on the render after the first one.

### Assigning state is silent

Assigning a state property never fires the grid's events (like a native `input.value`); methods and user
interaction do. `el.filters = …` no longer fires `filter-change` (the filter row and `setFilter()` still do;
`setFilter(field, text, { isSilent: true })` skips it); `el.focusedRowIndex = n` no longer fires `focus-change`.

### Loading states draw the shared loader

The infinite-scroll load-more row and the autocomplete's async search draw core `renderLoader()`'s default
`<span class="wg__loader">` (a `role="status"` container with an `aria-label`). Swap it with the new
`renderLoadingCallback` or page-wide `window.components.renderLoadingCallback`. The ⏳ pulse of the
autocomplete indicator and `@keyframes wg-pulse` are removed; the loader is themed by the new `--wg-loader-*`
tokens.

### Filtering ignores case and accents

The filter row, `setFilter()` and `filters` match through core `/search` "contains": case- and
accent-insensitive (`ces` finds `Český`; was `toLowerCase().includes`), the term trimmed (a blank filter
matches every row). The cell dropdown filters the same way. A column's `filterCallback` is unchanged — use it
for exact matching.

- **Motion:** `--wg-transition-fast` / `-normal` are durations only (`var(--base-duration-fast, 0.1s)` /
  `var(--base-duration-normal, 0.15s)`, were `0.1s ease` / `0.15s ease`); the easing is the new `--wg-easing`.

- **Toggle state:** `--wg-toolbar-btn-toggled-color` and `wg__toolbar-btn--toggled` /
  `wg__inline-action-btn--toggled`.
- `src/css/table.css` is `src/css/base.css` (deep imports only; `main.css` users are unaffected).
- `data-bs-theme` on `<web-grid>` itself no longer forces its scheme; use `data-theme` on the element.
  `data-bs-theme` on `<html>` / `<body>` / a `theme-source` section still works.

  `--base-danger-bg-subtle`, `--base-*-text-color`, `--base-tooltip-text-color`, …); the `--wg-*` names stay.

## Behaviour changes

### One tab stop in every edit mode

The grid follows the ARIA grid pattern, like Excel. Only the active cell has `tabindex="0"` (the first cell
before any focus), every other body cell `-1` (1.x: every cell `0` in navigate mode, and click / dblclick /
button grids had no cell in the tab order at all). Tab enters on the active cell and the next Tab / Shift+Tab
**leaves the grid**; arrows / Home / End / Page Up / Down / Ctrl+Home move the active cell. Navigation no longer
depends on `editTrigger` — the trigger only decides how an editor opens. Controls inside body cells (inline row
actions, the actions-column trigger, cell editors, `renderCellCallback` links / buttons marked
`data-wg-widget`) are `tabindex="-1"`: **Enter / F2** on such a cell moves into its first control, Tab /
Shift+Tab cycle them, Escape returns to the cell. With an editor open, Tab still saves and moves to the next
editable cell.

### Leaving a cell saves, Escape cancels

The Excel rule, for every editor: a click outside the grid, a click on another cell's calendar button or
dropdown toggle, another overlay opening (`dismissAllOverlays()`, a multiselect / date picker / menu),
`startEditing()` on another cell, the phone sheet's close button or Back — all **save** the edit (1.x: a click
outside cancelled). Escape cancels. `shouldCommitOnClickAway: false` keeps discarding. A scroll that moves the
edited cell still cancels; `items` replaced without the edited row cancels (`cell-edit-cancel`). An invalid
typed date is saved on leave and marked invalid (`errors.invalidDate`), as a pasted one; an async
`validateCallback` ends the edit at once and applies its result when it settles.

### Copy = what the cell shows

Without `getCopyValueCallback` a copy (single cell, range, row, column) takes the column's
`getDisplayValueCallback` text, else what the cell shows: a dropdown cell its option label (was the raw value),
a date cell its formatted date (was the ISO text), a number cell its locale-formatted number.
`getCopyValueCallback` now applies to range / row / column copies too (was single-cell only). Text pasted into
a dropdown column that matches an option's label stores that option's value.

### Number columns follow the locale

`editor: 'number'` cells show the locale's decimal separator and grouping for the grid's effective locale
(`locale` → page-wide `window.components.locale` → browser): `1,234.50` en-US, `1.234,50` de, `1 234,50` cs.
The editor opens with the locale decimal separator and no grouping; typed and pasted text is parsed with the
locale (core `parseNumber`, strict: a group separator only in a real group position — `1.5` in a `de` grid is
invalid, not a silent 15). The stored value stays a number. To keep one format everywhere set
`locale="en-US"` on the grid; `parseNumberCallback` reads text your own way.

### Typing and paste in every edit mode

Ctrl+V pastes at the focused cell in every `editTrigger` mode (1.x: navigate mode only); typing on an
`always` cell after Escape starts editing with that key; a number cell starts on the locale's decimal
separator too. Pasted text is typed by the column: numbers become numbers (were strings), checkbox and date
columns parse their text; text that doesn't parse is kept and the cell marked invalid.

### Render callbacks: `null` draws the built-in look

`renderCellCallback`, `editorOptions.renderOptionCallback`, `renderSummaryCallback`, `renderChevronCallback`
and `renderShortcutsHelpCallback` return a `RenderResult`: a string is HTML, a node is serialized,
**`null` / `undefined` draw the built-in look** (a cell used to show `null` / `undefined`, a chevron nothing),
`false` draws nothing. `renderCellCallback` now wins in every column type (dropdown, date and checkbox cells
ignored it or escaped it), and a column's `getDisplayValueCallback` is what a dropdown cell shows.

### Dark mode follows the page through core

The page signal (`data-theme`, `data-bs-theme`, `.dark` / `.light` on `<html>` / `<body>`) is read by core and
mirrored onto the grid as `data-context-theme`, instead of `:host-context()` (unsupported in Firefox, partial
in Safari — dark pages rendered a light grid there). A themed **wrapper** element now needs
`theme-source="closest"` on the grid.

### Where the overlays live

The cell / header menus, the cell dropdown and the date editor are in the grid's shadow root (1.x: menus and
the date editor in `document.body`, its styles in `<head>`), so they follow the grid's scheme and `--wg-*`
overrides. The column-reorder ghost and the toolbar connector are core layers (`.km-layer`) outside the grid.
Page scripts that queried them through `document` go through `el.shadowRoot` (Playwright locators pierce it).

### Scrolling stays in the grid

Keyboard moves, `scrollToRow()` and the go-to-row dialog scroll the one container around the cell (core
`scrollIntoContainer()`), not every ancestor; the page doesn't jump. `scrollToRow(rowIndex)` is public, centres
the row and resolves `false` when `beforeScrollCallback` skipped it.

### Paging, drafts and filters

A filter change goes back to page 1, a shorter `items` clamps `currentPage`, a header-menu sort resets to page 1.
Drafts are never pruned when `items` is set (server paging: a missing row is another page).

### Smaller

- Shortcut texts are core `formatShortcut`: platform key names (`Delete` → `Del`, `ArrowUp` → `↑`, Apple
  `⇧⌘D`); configured `rowShortcuts` / `rangeShortcuts` win over the grid's own keys (Delete, F2, typing).
- Tooltips show on keyboard focus too and are placed by core (flip + shift; no left / right fallback).
- The row toolbar closes through core's overlay tree: Escape closes it; 'click' / 'button' toolbars join the
  grid's `overlay-group`.
- Unset `isRowEditable` reads back `null` (was `undefined`).
- The Ctrl+G go-to-row dialog is a real modal (inert page, Tab trap, phone Back cancels).

## New features — inputs, lifecycle and state

### `readonly` / `disabled`

`isReadonly` / `readonly`: no editing, paste, fill or row add / delete / duplicate / move (those built-ins are
disabled); the grid stays focusable, selectable and copyable. The `read-only` preset sets it. `isDisabled` /
`disabled`: no interaction — the container is `inert` and dimmed.

### Core lifecycle

`defer` / `shouldDefer` holds the first render until `release()`; then the `ready` event (`onReady`), the
`ready` attribute, `:state(ready)` and `whenReady()`. `destroy()` is core's. Inputs and `columns` / `items`
assigned before `<web-grid>` is defined are applied at upgrade.

### Responsive rules

Partial configs per device class (`device`) or window-width breakpoint (`breakpoint`), from the page
(`window.components.responsive`), the tag (`window.components['web-grid'].responsive`) or the instance
(`el.responsive` / `responsive` JSON attribute / `responsiveCallback`):

```js
grid.responsive = { device: { mobile: { pageSize: 10, isRowNumbersShown: false } } };
```

### More inputs

`overlay-group` (scopes "one overlay open at a time"), `menu-presentation` (`auto | floating | sheet | drawer`)
/ `menu-side`, `fill-direction` (`vertical | all`), `filter-mode` (`client | server`), `edit-button-icon`,
`storage-key` + `loadStateCallback` / `saveStateCallback`, `locale`, `parseNumberCallback`,
`translateCallback`, `renderIconCallback`, `renderLoadingCallback`, `beforeScrollCallback`,
`beforePageChangeCallback`, `beforeActionCallback`, and attributes for the row-identity / tree members
(`id-member`, `path-member`, `level-member`, `parent-path-member`, `tree-path-separator`, `expand-level`,
`row-editable`, `toolbar-btn-min-width`). `enable-virtual-scroll="auto"` (property `null`) switches to virtual
scroll once the displayed rows reach `virtual-scroll-threshold`; the default stays `false`.

### Drafts list and page guard

`getDrafts()` (element + controller) and `ctx.drafts` in `renderSummaryCallback` list every unsaved draft
`{ row, draftRow, changedFields, isValid }`, also on other pages; `discardDraft(row)` drops one.
`beforePageChangeCallback(ctx)` runs before a pager button, page-size change, header sort or filter change swaps
the rows in server pagination: `false` stays, a number goes to that page (async OK — "save before leaving").

## New features — editing, clipboard and data

### Filter row

`isFilteringEnabled` renders a row of text inputs under the header for every column with
`isFilterable: true` (it was API-only): debounced, IME-safe, Enter applies, Escape clears; a `filterCallback`
returning `null` marks the input `.wg__filter-input--invalid`; in server mode a change fires `data-request`
(`trigger: 'filter'`).

### Editing

- The number editor validates: a non-number, a value outside `min` / `max`, a negative with

- `editorOptions.isEmptyAllowed` adds an empty first item to select / combobox / autocomplete (→ `null`).
- `isCheckboxAlwaysEditable` works: one click toggles a display checkbox.
- The autocomplete search is "latest request wins" (core `createAsyncRunner`): the `searchCallback`'s `signal`

Copy falls back to `execCommand('copy')` when the Clipboard API refuses (an `http://` intranet page, an
embedded webview).

### Selection events

New `row-selection-change` `{ rows, rowIndices }` and `column-selection-change` `{ fields }`;
`cell-selection-change` gains `fields` and `rows`.

## New features — localization

### Page-wide labels and `translateCallback`

Besides the instance `labels` (also a JSON attribute), one page-wide flat dictionary of full keys translates
every grid:

|---|---|
| `el.controller` (`GridController`) | the public facade; also `insertRow(s)`, `removeRow(s)`, `duplicateRow`, `moveRow`, column selection, `closeContextMenu`, `closeToolbar` |
| Methods | `scrollToRow(rowIndex)`, `getRowById(id)`, `getRowIndex(row)`, `getDrafts()`, `discardDraft(row)`, `clearRowSelection()`, `expandRows()` / `collapseRows()`, `setAttributes()`, `batch()`, `release()`, `whenReady()`, `destroy()` |
| Events | `action`, `row-selection-change`, `column-selection-change`, `row-expand`, `row-collapse`, `expanded-change`, `cell-paste`, `ready`, `input-rejected` (+ every renamed event above) |
| Exports | `createMenuDivider`, `GridElementConfig`, `GridResponsiveMap` / `GridResponsiveCallback`, `RenderResult`, `ExpandOptions`, every ctx / item / event-detail type (`GridContext`, `CellContext`, `HeaderMenuContext`, `GridToolbarItem`, `GridMenuEntry`, `GridShortcut`, `GridActionEventDetail`, `GridEventMap`, …) |
| Editor data | `custom-elements.json`, `web-types.json`, `vscode.html-custom-data.json`, `vscode.css-custom-data.json` ship with the package |

## Visible changes without a migration

- Context menus: 14px font (was 13px), item padding 6px 12px (was 8px 12px), submenu arrow ▸ (was ▶), a focus
  highlight on the keyboard-focused item, toggled column toggles in the accent colour; menu z-index 9001
  (was 10000).
- Standalone accent `#3b82f6` (was Fluent `#0078d4`), text `#334155` / `#f1f5f9`, main bg `#ffffff` /
  `#1e293b`; accent tint 10% / 20% (was 15%).
- The cell dropdown opens 4px below the cell (was 1px) — `--base-dropdown-offset`.
- Tree indent 16px per level (was 20px, `--base-tree-indent`).
- The column-reorder drop indicator is green (`--base-drop-target-border-color`, was the accent blue).
- Disabled dimming 0.65 everywhere (was 0.6 / 0.5 / 0.4).
- The column resize handle sits inside its header cell (`--wg-resize-handle-offset: 0px`, was `-6px`).
- Number cells show locale grouping (`1,234.50`).
- A row-action button / in-cell control shows its own focus ring; the data cell's ring steps back meanwhile.
- The dropdown panel stays hidden until its first placement (no flash at the top-left).

## Fixes

### Editing and validation

- A combobox left by a click on another cell saved the option's label instead of its value; Tab on a
  combobox / autocomplete without arrowing cancelled and lost the typed text.
- An open text / number / combobox editor keeps its typed text and caret through a re-render (also the
  normal ↔ virtual switch); an open dropdown re-anchors to its cell after a re-render.
- Enter on the last row commits an `always` editor; a typed date is no longer lost on leave; Shift+Tab in the
  date picker moves to the previous cell; a date cell with invalid text shows the text, not a rolled-over date.
- Opening an editor and cancelling no longer leaves a phantom draft (`isRowDirty` is value-based); the
  row-number dirty marker updates right after a commit; the summary re-renders after a cell edit.
- Paste validation treats `null` as valid, like an editor commit; `startEditing()` no longer renders an editor
  into a read-only / locked cell.

### Selection, keyboard and scroll

- Cell ranges, the fill handle and column selection with reordered or hidden columns addressed the wrong
  columns.
- Keyboard moves in a virtual grid land on the target cell outside the rendered window; Shift+Arrow extends
  past it; two quick Shift+Arrows no longer grow the range by one; a fast drag no longer selects a stale range.
- Escape right after a header / row-number click clears the selection.
- Focus follows the row on move-up / move-down; go-to-row Escape / Cancel returns focus to the cell; a grid
  inside another component's shadow root keeps its focused cell.
- `scrollToRow()` / go-to-row in a virtual grid honour the block and land flush under the sticky header.

### Toolbar, menus and tooltips

- The row toolbar state is per grid (another grid's render could act on it); its buttons refresh after a
  built-in; shortcuts on an open toolbar follow the moved row; a row shortcut no longer fires twice; a closed
  toolbar no longer leaves its connector line.
- A cell tooltip's content is resolved when it opens; a tooltip on the next cell is no longer removed by the
  previous one's fade-out; `tooltipHideDelay` is honoured when the pointer leaves the grid; the
  validation-error tooltip updates with the cell.
- The shortcuts help lists `rangeShortcuts`; Cmd+G and Cmd+Delete work on macOS.

### Data and security

- **Security:** attribute values were not quote-escaped — row data in a tooltip or a cell value could inject
  attributes. `"` and `'` are escaped everywhere.
- A filter on a later client page rendered "Page 3 of 1"; the expanded-paths change detail handed out the
  grid's live `Set` (now a snapshot array); persisted column state was wiped when the storage key was set
  before `columns`.
- One document `mouseup` listener per grid (every full rebuild added another — a detached grid stayed
  reachable); the toolbar's row-shortcut `keydown` listener is dropped on disconnect.
