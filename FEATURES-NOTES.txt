1. ROW FOCUS (FOR MASTER/DETAIL)
================================================================================

PURPOSE:
- When clicking anywhere on a row in read-only mode, the row becomes "focused"
- Used for master/detail patterns where clicking a row shows details elsewhere
- Different from cell focus (which is for editing/navigation)

STATE:
- _focusedRowIndex: number | null  (protected in grid.ts)
- Getter/setter: focusedRowIndex

API:
- focusedRowIndex: number | null   - get/set the focused row
- row-focus event / onRowFocus(detail) - fires when row focus changes
- isRowFocused(rowIndex): boolean  - check if row is focused
- clearRowFocus(): void            - clear focus

RowFocusDetail type (types.ts:254):
  {
    rowIndex: number
    row: T
    previousRowIndex: number | null
  }

CSS CLASSES:
- .wg__row--focused - applied to the <tr> element
- Styles in _table.css (lines 81-116):
  - Row number cell gets --wg-row-focus-row-number-bg background
  - Data cells get --wg-row-focus-bg background + top/bottom borders
  - First cell gets left border, last cell gets right border
  - Uses box-shadow for borders (inset technique)
- Frozen column override in _freeze.css (line 70)

HOW IT'S TRIGGERED:
- Click on row when grid is NOT editable (isEditable: false)
- Or when cell is not editable
- Sets focusedRowIndex and fires the row-focus event (onRowFocus twin)

RENDERING:
- table.ts lines 378 and 673: adds .wg__row--focused class based on isRowFocused()

2. COLUMN RESIZE (VERTICAL SPLITTERS)
================================================================================

PURPOSE:
- Drag the edge of a column header to resize the column width
- Visual feedback during resize
- Persists (core state store) if storage-key + persist-column-widths are set

FILES:
- modules/resize/index.ts - main logic
- css/_resize.css - styling for resize handle

KEY CONCEPTS:

ResizeState interface:
  {
    isResizing: boolean
    startX: number
    startWidth: number
    field: string
    headerCell: HTMLElement | null
    minWidth: number
    maxWidth: number | null
  }

FLOW:
1. handleResizeStart() - mousedown on resize handle
   - Gets column min/max from column definition
   - Stores startX, startWidth
   - Adds .wg--resizing class to container
   - Attaches document-level mousemove/mouseup listeners

2. handleDocumentMouseMove() - during drag
   - Calculates deltaX from startX
   - Clamps to min/max width
   - Updates header cell width inline (immediate feedback)
   - Updates all body cells in column via updateAllColumnCells()
   - If frozen columns: updates left offsets via updateFrozenColumnOffsets()

3. handleDocumentMouseUp() - end drag
   - Calculates final width
   - Stores in grid state via setColumnWidth(field, width, skipRender=true)
   - Updates <col> element in colgroup
   - Fires the column-resize event (onColumnResize twin)
   - Persists to localStorage if enabled
   - Cleans up listeners and state

COLUMN DEFINITION OPTIONS:
- isResizable: boolean (default true) - can disable per column
- minWidth: string (e.g., "50px") - minimum width (default 30px)
- maxWidth: string (e.g., "300px") - maximum width (optional)

PERSISTENCE:
- If shouldPersistColumnWidths=true and storageKey is set
- Saves to localStorage via savePersistedWidths()

CSS:
- .wg__resize-handle - the draggable element (positioned at right edge of header)
- .wg__resize-handle--active - while dragging
- .wg--resizing - on container during resize (cursor: col-resize)

3. NEW EMPTY ROW (INLINE DATA ENTRY)
================================================================================

PURPOSE:
- An always-visible empty row for quick data entry
- User types in the row, presses Enter to commit
- After commit, a fresh empty row appears automatically

REQUIREMENT: NAVIGATE MODE
- The empty row feature REQUIRES editTrigger: "navigate" to work properly
- Tab navigation between cells is a navigate mode behavior
- Without navigate mode, Tab doesn't move focus between cells

STATE:
- _isNewRowEnabled: boolean (default false)
- _newRowPosition: 'top' | 'bottom' (default 'bottom')
- _createEmptyRowCallback: (() => T | Promise<T>) | undefined
- _emptyRowDraft: T | null - tracks edits before commit
- _isEmptyRowLoading: boolean - for async callback

API:
- isNewRowEnabled: boolean
- newRowPosition: 'top' | 'bottom'
- createEmptyRowCallback: () => T | Promise<T>  (can be async!)
- newRowIndicator: string (default '+')

HOW IT WORKS:

1. Display:
   - displayItems getter appends/prepends empty row based on newRowPosition
   - getEmptyRow() returns cached _emptyRowDraft or creates new via createNewEmptyRow()
   - Row number shows newRowIndicator ('+') instead of number

2. Index handling:
   - isEmptyRowIndex(displayIndex) - checks if index is the empty row
   - getDataIndexFromDisplayIndex(displayIndex) - converts display index to data index
   - Empty row at top: displayIndex 0 is empty, data starts at 1
   - Empty row at bottom: last displayIndex is empty

3. Editing (THE TRICKY PART):
   - User clicks cell in empty row, starts editing
   - User types value
   - On Tab: save value to _emptyRowDraft, move to next cell, DON'T commit row
   - On Enter: if row has data, commit to items[] and fire the row-change event

4. Commit logic (commitEdit in grid.ts):
   - Takes commitEmptyRow: boolean parameter
   - If editing empty row and commitEmptyRow=true (Enter pressed):
     - Check if row has any data via emptyRowHasData()
     - If yes: add to _items[], fire row-change, reset _emptyRowDraft to null
   - If commitEmptyRow=false (Tab pressed):
     - Just update _emptyRowDraft, exit edit mode, keep draft

5. Draft handling:
   - _emptyRowDraft caches the current empty row state
   - getCellRawValue() must skip _draftRows lookup for empty row index
     (otherwise it returns stale data from regular draft system)
   - getEmptyRow() caches result immediately to avoid multiple callback calls

CSS:
- .wg__row--empty-row - on the empty row <tr>
- .wg__empty-row-indicator - the '+' indicator in row number cell

PROBLEMS WE ENCOUNTERED:
1. Tab was committing the row - fixed with commitEmptyRow parameter
2. Value disappeared after Tab - _draftRows and _emptyRowDraft conflicted
3. createEmptyRowCallback called multiple times - needed caching
4. tabindex was null on empty row cells - focusCellElement needed to add it
5. Keyboard navigation didn't work - grid wasn't in navigate mode!

4. NAVIGATE MODE vs CLICK-TO-EDIT
================================================================================

editTrigger options:
- "dblclick" (default) - double-click to edit
- "click" - single click to edit
- "navigate" - cells are focusable, click to focus, Enter/F2 to edit
- "always" - always in edit mode (for forms)

isNavigateMode getter:
- Returns true if editTrigger === "navigate" OR any column has editTrigger: "navigate"

NAVIGATE MODE BEHAVIOR:
- Cells have tabindex="0" (focusable)
- Click focuses cell (doesn't start edit)
- Arrow keys move focus between cells
- Tab moves to next editable cell
- Enter/F2 starts editing
- Escape exits edit mode and focuses cell
- Enter in edit mode commits and moves down

CLICK-TO-EDIT BEHAVIOR:
- Click starts editing immediately
- No focused state between edits
- Tab behavior is browser default (moves to next focusable element)
- No arrow key navigation

5. TECHNICAL DETAILS FOR REIMPLEMENTATION
================================================================================

SURGICAL CELL UPDATES:
- renderCell() in modules/rendering/cell.ts
- Updates a single cell's DOM without full re-render
- Handles classes, content, editor focus
- Call this instead of requestUpdate() for single cell changes

FOCUS MANAGEMENT:
- focusCellElement() in modules/navigation/focus.ts
- Must add tabindex="0" if missing (cells are <td>, not naturally focusable)
- Uses cell.focus({ preventScroll: true }) then scrollIntoView

DRAFT SYSTEM:
- _draftRows: Map<rowIndex, draftRow> - for regular rows during edit
- _emptyRowDraft: T | null - separate draft for empty row
- getCellRawValue() checks _draftRows first, then falls back to item
- For empty row: skip _draftRows check, use item directly (which is _emptyRowDraft)

ASYNC CALLBACK:
- createEmptyRowCallback can return Promise<T>
- createNewEmptyRow() handles both sync and async
- Sets _isEmptyRowLoading while waiting
- Caches result in _emptyRowDraft when resolved

COMMIT FLOW:
1. User presses Enter/Tab in editor
2. Keyboard handler calls commitCurrentEditor(ctx, editor, commitEmptyRow)
3. commitCurrentEditor extracts value and calls ctx.engine.commitEdit(...)
4. commitEdit validates, updates draft, optionally adds to items
5. Keyboard handler calls moveFocusAfterCommit() for Tab, or handles focus for Enter

// Grid must be in navigate mode for Tab to work
grid.editTrigger = 'navigate'
grid.isEditable = true
grid.isNewRowEnabled = true
grid.newRowPosition = 'bottom'  // or 'top'

// Optional: custom factory for default values
grid.createEmptyRowCallback = () => ({
  id: generateId(),
  name: '',
  status: 'draft',
  createdAt: new Date()
})

// Or async version:
grid.createEmptyRowCallback = async () => {
  const defaults = await fetchDefaults()
  return { id: generateId(), ...defaults }
}
