TOOLBAR, INLINE ACTIONS, CELL TOOLBAR, AND CONTEXT MENUS
=========================================================
Reference for @keenmate/web-grid row toolbar, inline actions,
cell-specific toolbar, and context menus (cell and header).

Every toolbar button, menu item and keyboard shortcut is an ACTION ITEM
(the shared KeenMate interaction model, @keenmate/web-components-core
/actions). Activating any of them runs the same pipeline:

    1. beforeActionCallback(detail)   -> return false to cancel (async OK)
    2. the item's onClick(detail)     -> awaited
    3. the built-in (only when the item names a built-in `action`)
    4. the `action` DOM event + the onAction(detail) twin — a notification
       after the fact (a throwing built-in is logged; the event still fires)

`detail` is the same object at every step (see THE ACTION EVENT below).


ROW TOOLBAR BASICS
------------------
The row toolbar is a floating (or inline) set of action buttons
that appear per-row. Enable it with two properties:

    grid.isRowToolbarShown = true
    grid.rowToolbar = ['add', 'delete', 'duplicate', 'move-up', 'move-down']

The rowToolbar array (GridToolbarEntry<T>[]) accepts built-in names,
action item objects and dividers, mixed in any order. Default:
['add', 'delete', 'duplicate'].

Built-in row actions (they DO the work, after the `action` event):
    'add'        - Insert a new row after the current row. The row is
                   createEmptyRowCallback(ctx)'s result (may be async),
                   else a blank row (every column field = null).
    'delete'     - Remove the target rows from items.
    'duplicate'  - Insert a copy after each target row:
                   createDuplicateRowCallback({ row })'s result, else a
                   shallow copy with idMember cleared.
    'move-up'    - Move the target rows one displayed position up, as a
                   block (disabled when the block is at the top).
    'move-down'  - Same, down (disabled at the bottom).

Targets: the whole row selection when the clicked / focused row is in it,
else just that row (range shortcuts: their rows) - the same rule as the
tree actions. 'add' always inserts after the clicked row. The row
selection follows its rows afterwards (deleted rows drop out); a row
toolbar opened on a selected row keeps the selection.

Each built-in gets a default SVG icon and text (labels.actions);
'delete' is isDanger. Override any of it with an object:

    { action: 'delete', icon: '🗑️', text: 'Remove task' }

IMPORTANT: do not also add / delete / move rows yourself in onAction or
onClick for a built-in item - the row would change twice. Use the
built-ins (+ the two factory callbacks to shape new rows) and keep only
side effects (toasts, logging, server calls) in onAction. To handle a
button entirely yourself, make it a CUSTOM item (an `id`, no `action`).

    grid.createEmptyRowCallback = () => ({ id: nextId(), name: 'New', qty: 0 })
    grid.createDuplicateRowCallback = ({ row }) => ({ ...row, id: nextId(), name: row.name + ' (copy)' })

Veto any activation (e.g. a confirm dialog):

    grid.beforeActionCallback = async (detail) => {
      if (detail.action === 'delete') return await confirmDialog('Delete ' + detail.row.name + '?')
    }

Toolbar trigger controls how the toolbar appears:
    grid.toolbarTrigger = 'hover'   (default) show on row hover
    grid.toolbarTrigger = 'click'   show on row click
    grid.toolbarTrigger = 'button'  show a trigger button in each row

When toolbarTrigger is 'button', a column with a vertical ellipsis
button is rendered. Clicking the button opens the floating toolbar.


TOOLBAR ITEMS
-------------
An item object (GridToolbarItem<T>, ctx = RowContext<T> = { row, rowIndex,
controller, element }):

    {
      action?: GridRowAction        // built-in name ('add' | 'delete' | 'duplicate' | 'move-up' | 'move-down')
      id?: string                   // identifies a custom item (reported in the action event)
      text?: string                 // accessible name + tooltip heading; shown as a label only
                                    //   when there is no icon or isTextVisible is true
      icon?: string                 // icon HTML / emoji / SVG
      tooltip?: string              // tooltip description line (under the heading)
      shortcut?: string             // key hint line in the tooltip (e.g. 'Ctrl+D'); also taken from a
                                    //   rowShortcuts entry with the same id
      isDanger?: boolean            // destructive styling
      isDisabled?: boolean          // greyed out, not clickable
      isVisible?: boolean           // default true
      isToggled?: boolean           // toggle state: aria-pressed="true" + --toggled class
      cssClass?: string             // extra CSS classes (e.g. a per-button min-width)
      getTextCallback?(ctx) / getIconCallback?(ctx) / getTooltipCallback?(ctx) / getClassCallback?(ctx)
      getIsVisibleCallback?(ctx) / getIsDisabledCallback?(ctx) / getIsToggledCallback?(ctx)
      onClick?(detail)              // detail = the action event detail; awaited
      row?: number                  // toolbar row, 1 = closest to the grid row (default 1)
      isTextVisible?: boolean       // show `text` next to the icon
    }

Dividers: an entry { divider: true } (optionally { divider: true, text: 'Group' })
separates buttons; `menuDivider(text?)` (exported) builds one.

Example with built-ins, custom items and a divider:

    import { menuDivider } from '@keenmate/web-grid'

    grid.rowToolbar = [
      'move-up',
      'move-down',
      menuDivider(),
      'add',
      { action: 'delete', icon: '🗑️', text: 'Delete' },
      {
        id: 'edit',
        icon: '<svg>...</svg>',
        text: 'Edit record',
        tooltip: 'Open editor',
        shortcut: 'Enter',
        getIsDisabledCallback: ({ row }) => row.isLocked,
        getIsVisibleCallback: ({ row }) => !row.isArchived,
        onClick: ({ row }) => openEditor(row)
      },
      {
        id: 'archive',
        icon: '📦',
        text: 'Archive',
        isTextVisible: true,
        row: 2,
        isDanger: true,
        onClick: ({ row }) => archiveRow(row)
      }
    ]

Multi-row layout:
- Items with the same 'row' number appear on the same horizontal row.
- Row 1 is closest to the grid data row. Higher row numbers stack
  outward from the data row.
- Divider entries separate groups within a row.


TOOLBAR POSITIONING
-------------------
Properties that control where and how the toolbar appears:

    grid.toolbarPosition = 'auto'     (default) prefers left, falls back to right, then top
    grid.toolbarPosition = 'left'     to the left of the row
    grid.toolbarPosition = 'right'    to the right of the row
    grid.toolbarPosition = 'top'      above the row
    grid.toolbarPosition = 'inline'   renders as a fixed table column (see INLINE ACTIONS)

For left/right positions, vertical alignment controls where the
toolbar aligns relative to the row:

    grid.toolbarVerticalAlign = 'bottom'   (default) toolbar top aligns with row, stacks downward
    grid.toolbarVerticalAlign = 'center'   toolbar centered on row
    grid.toolbarVerticalAlign = 'top'      toolbar bottom aligns with row, stacks upward

For top position, horizontal alignment controls left-right placement:

    grid.toolbarHorizontalAlign = 'center'   (default) centered above row
    grid.toolbarHorizontalAlign = 'start'    aligned with left edge
    grid.toolbarHorizontalAlign = 'end'      aligned with right edge
    grid.toolbarHorizontalAlign = 'cursor'   positioned at mouse cursor X

Additional positioning properties:

    grid.shouldToolbarFollowCursor = false     (default) toolbar stays at initial position
    grid.shouldToolbarFollowCursor = true      toolbar follows mouse cursor horizontally

    grid.toolbarColumn = 'fieldName'      pin toolbar above a specific column (for 'top' position)
    grid.toolbarColumn = 2                or by column index

    grid.toolbarBtnMinWidth = '32px'      min-width for toolbar buttons (CSS value)
                                          overrides --wg-toolbar-btn-min-width variable

    grid.cellToolbarOffset = 0.2          (default) horizontal offset for cell toolbar
                                          number 0-1: fraction of cell width
                                          string: CSS length like '2rem' or '24px'

Deprecated aliases:
    toolbarAlign         -> use toolbarVerticalAlign
    toolbarTopPosition   -> use toolbarHorizontalAlign
    toolbarFollowsCursor -> use shouldToolbarFollowCursor

The toolbar uses @floating-ui/dom for smart positioning with automatic
flip and shift. If the preferred position would go off-screen, it
falls back to alternative positions.

Connector arrow: When move-up / move-down actions are used, a bracket-shaped
SVG connector line tracks from the toolbar to the row's current position,
even when the row scrolls out of view.


INLINE ACTIONS
--------------
When toolbarPosition is set to 'inline', toolbar items render as a
fixed column in the table instead of a floating popup.

    grid.isRowToolbarShown = true
    grid.toolbarPosition = 'inline'
    grid.rowToolbar = ['add', 'delete', 'duplicate']

Behavior differences from floating toolbar:
- Actions render as buttons directly in each row's cell.
- No hover/click trigger needed; buttons are always visible.
- No floating-ui positioning; it is a regular table column.
- Hidden items (isVisible / getIsVisibleCallback false) are excluded from the DOM.
- Disabled items render as disabled buttons.
- Multi-row layout (via the 'row' property) is supported within the cell.

Column header title:

    (default)                                     "Actions"
    grid.labels = { inlineActionsHeader: 'Ops' }  custom header text
    grid.labels = { inlineActionsHeader: '' }     no header text

The column width auto-sizes based on the maximum number of buttons
across all rows, using --wg-toolbar-btn-min-width and --wg-inline-actions-gap
CSS variables.

Clicking an inline action button runs the same pipeline as the floating
toolbar (onClick, the `action` event / onAction with source 'row-toolbar',
then the built-in).


CELL-SPECIFIC TOOLBAR
---------------------
getCellToolbarItemsCallback provides context-sensitive toolbar items
that appear when hovering/clicking a specific cell, not just a row.

    grid.getCellToolbarItemsCallback = ({ row, rowIndex, column, colIndex, field, value }) => {
      if (field === 'status') {
        return [
          { id: 'approve', icon: '✅', text: 'Approve', onClick: ({ row }) => approve(row) },
          { id: 'reject', icon: '❌', text: 'Reject', isDanger: true, onClick: ({ row }) => reject(row) }
        ]
      }
      return undefined   // no cell toolbar for other columns
    }

Callback signature:
    getCellToolbarItemsCallback: (ctx: CellContext<T>) => GridToolbarEntry<T>[] | null | undefined

Return toolbar entries (same format as rowToolbar - built-in names, items,
dividers); they are merged over rowToolbar by id / action. Return
undefined / null for no cell toolbar. Clicks report source 'cell-toolbar'
and carry the cell fields (column, colIndex, field, value).

The cell toolbar position is controlled by cellToolbarOffset:

    grid.cellToolbarOffset = 0.2    (default) 20% from left edge of the cell
    grid.cellToolbarOffset = 0      left edge of cell
    grid.cellToolbarOffset = 0.5    center of cell
    grid.cellToolbarOffset = '2rem' 2rem from left edge of cell

When the callback returns items, the toolbar appears above the hovered
cell. When it returns undefined, the regular row toolbar (if configured)
is used instead. The toolbar uses 'top' position when showing
cell-specific items.


CONTEXT MENU
-------------
Right-click context menu for data cells/rows. Entries (GridMenuEntry<T>):
built-in names, menu items, dividers.

    grid.contextMenu = [
      {
        id: 'view',
        text: 'View Details',
        icon: '👁️',
        shortcut: 'Enter',
        onClick: (detail) => viewDetails(detail.row)
      },
      { divider: true, text: 'Rows' },
      'duplicate',
      {
        action: 'delete',
        text: 'Delete Row',
        icon: '🗑️',
        shortcut: 'Delete',
        getIsDisabledCallback: (ctx) => ctx.row.isLocked
      },
      {
        id: 'more',
        text: 'More',
        getChildrenCallback: async (ctx) => [
          { id: 'export', text: 'Export ' + ctx.row.name, onClick: (d) => exportRow(d.row) }
        ]
      }
    ]

Built-in names in the cell menu:
    row:  'add' | 'delete' | 'duplicate' | 'move-up' | 'move-down'  (same work as the toolbar)
    tree: 'expand'           - expand one level (hidden on leaves)
          'collapse'         - collapse (hidden on leaves)
          'expand-subtree'   - expand the row and everything under it (hidden on leaves)
          'collapse-subtree' - collapse the row and everything under it (hidden on leaves)
          the per-row tree items act on the whole row selection when the clicked
          row is in it, else just the clicked row
          'expand-all'   - expand the whole tree (tree mode only)
          'collapse-all' - collapse the whole tree (tree mode, something expanded)

Menu item (GridMenuItem<T>, ctx = CellContext<T>):

    {
      action?: GridCellAction        // a built-in name
      id?: string                    // identifies a custom item
      text?: string                  // label
      icon?: string
      tooltip?: string
      shortcut?: string              // display hint; also activates the item while the menu is open
      isVisible?: boolean            // default true
      isDisabled?: boolean
      isDanger?: boolean
      isToggled?: boolean            // toggle state (menuitemcheckbox + aria-checked, checkmark styling)
      cssClass?: string
      getTextCallback?(ctx) / getIconCallback?(ctx) / getTooltipCallback?(ctx) / getClassCallback?(ctx)
      getIsVisibleCallback?(ctx) / getIsDisabledCallback?(ctx) / getIsToggledCallback?(ctx)
      onClick?(detail)               // awaited
      children?: GridMenuEntry<T>[]  // static submenu
      getChildrenCallback?(ctx)      // dynamic / lazy submenu (sync or async; a loading row shows meanwhile)
      shouldCloseOnClick?: boolean   // default true
    }

Cell ctx (CellContext<T>):

    {
      row: T                 // the row data object
      rowIndex: number       // displayed row index
      column: Column<T>      // the column definition
      colIndex: number       // index in columns
      field: string          // column field
      value: unknown         // the cell's value (draft value when the row has one)
      controller, element    // non-enumerable
    }

Shortcut matching: When the context menu is open, pressing a key that
matches an item's shortcut string (case-insensitive for single letters)
activates that item.

Before-open hook (sync):

    grid.beforeContextMenuOpenCallback = (ctx) => {
      if (ctx.field === 'id') return false             // no grid menu (the browser's shows)
      if (ctx.row.isLocked) return [{ id: 'unlock', text: 'Unlock' }]   // shown instead
      // undefined -> contextMenu as configured
    }

Positioning offsets:

    grid.contextMenuXOffset = 8    (default) horizontal offset from click
    grid.contextMenuYOffset = 0    (default) vertical offset from click

Both menus are the shared KeenMate menu (core openMenu(),
@keenmate/web-components-core/menu), rendered in the grid's shadow root
(.km-menu, plus .wg-context-menu on cell menu levels / .wg-header-menu on
header menu levels), positioned viewport-aware (flip / shift). Keyboard: see
CSS VARIABLES below (Shift+F10 / ContextMenu key opens the cell menu).

Closing behavior:
- Click outside the menu
- Press Escape (focus returns to where it was) or Tab
- Scroll the page or grid, window blur, another KeenMate overlay opening
- Activating an item (unless shouldCloseOnClick: false)
- el.controller.closeContextMenu()


HEADER CONTEXT MENU
-------------------
Right-click context menu for column headers with built-in actions
and custom items (GridHeaderMenuEntry<T>).

    grid.headerContextMenu = [
      'sort-asc',
      'sort-desc',
      'clear-sort',
      { divider: true },
      'hide-column',
      'freeze-column',
      'unfreeze-column',
      'column-visibility',
      {
        id: 'custom-action',
        text: 'Custom Action',
        icon: '⚙️',
        onClick: (detail) => doSomething(detail.column)
      }
    ]

Built-in names:

    'sort-asc'           - Sort column ascending (hidden if column not sortable)
    'sort-desc'          - Sort column descending (hidden if column not sortable)
    'clear-sort'         - Clear sort for this column (hidden if not sorted)
    'hide-column'        - Hide this column (sets isHidden=true; hidden for the tree column)
    'freeze-column'      - Freeze columns up to and including this one (hidden if already frozen)
    'unfreeze-column'    - Unfreeze this column (hidden if not frozen)
    'column-visibility'  - Submenu with "Show all" + a toggle per column

A sort from the header menu also fires `data-request` (trigger 'sort').
The column-visibility submenu stays open after toggling items, updating
checkmarks (isToggled) in real time. Its entries report action
'show-all-columns', and 'toggle-column' with id = the column field.

Header menu items have the same shape as cell menu items, with ctx =
HeaderMenuContext<T>:

    {
      column: Column<T> | null   // null on the filler area right of the last column
      field: string              // '' on the filler
      colIndex: number           // index in columns; -1 on the filler
      sortDirection: 'asc' | 'desc' | null
      isFrozen: boolean
      isTreeMode: boolean
      allColumns: Column<T>[]    // all columns including hidden
      labels: GridLabels         // grid labels for i18n
      controller, element        // non-enumerable
    }

Before-open hook (sync), same contract as the cell menu:

    grid.beforeHeaderMenuOpenCallback = (ctx) => {
      if (ctx.column === null) return false
    }

Submenus: `children` for a static array, `getChildrenCallback(ctx)` for
a dynamic / lazy one (sync or async). Every child item activates
(onClick, the action event) like a top-level item.

Built-ins are matched by `action` only; an `id` always identifies a
custom item (a custom item with id 'sort-asc' does NOT sort).


ROW AND RANGE SHORTCUTS
-----------------------
rowShortcuts are action items bound to a key, run on the focused /
hovered row; `action` may name a row built-in:

    grid.rowShortcuts = [
      { shortcut: 'Ctrl+D', action: 'duplicate' },
      { shortcut: 'Ctrl+E', id: 'export', text: 'Export', onClick: ({ row }) => exportRow(row) }
    ]

rangeShortcuts act on the selected rows / cell range (custom only),
ctx = { rows, rowIndices, cellRange?, cells? }:

    grid.rangeShortcuts = [
      { shortcut: 'Ctrl+Shift+E', id: 'export-sel', text: 'Export selection', onClick: ({ rows }) => exportRows(rows) }
    ]

See keyboard-navigation.txt for details.


THE ACTION EVENT
----------------
Every toolbar, inline, cell-toolbar, menu and shortcut item fires the
`action` DOM event (bubbles, not composed) and its camelCase twin
onAction (called with the same detail first).

    grid.onAction = (detail) => {
      if (detail.action === 'add') toast('Row added')
      else if (detail.id === 'archive') toast('Archived ' + detail.row.name)
    }
    // or
    grid.addEventListener('action', (e) => console.log(e.detail.action, e.detail.id))

Detail (GridActionEventDetail<T>):

    {
      action: string             // built-in name, or 'custom'
      id?: string                // the item's id
      item: object               // the item definition
      source: 'row-toolbar' | 'cell-toolbar' | 'context-menu' | 'header-menu' | 'keyboard'
      sourceEvent?: Event        // the click / keydown
      triggerElement?: HTMLElement  // the clicked button (usable as a Floating UI anchor)
      dataset: Record<string, string>  // the trigger's data-* attributes
      // surface fields:
      row, rowIndex                          // row surfaces
      column, colIndex, field, value         // cell surfaces
      sortDirection, isFrozen, allColumns, … // header menu
      rows, rowIndices, cellRange, cells     // range shortcuts
      controller, element                    // non-enumerable
    }

Order: beforeActionCallback -> item.onClick -> built-in -> action event
/ onAction. So in onAction for 'add' the new row is already in items;
for 'delete' the row is gone; for 'move-up' / 'move-down' items has the
new order. detail.row / rowIndex are the context captured before.

Buttons and menu items carry data-action (built-in name or 'custom')
and data-id attributes.


I18N LABELS
-----------
Relevant labels that can be customized:

    grid.labels = {
      rowActions: 'Row actions',      // toolbar trigger button title
      inlineActionsHeader: 'Actions', // default inline actions column header
      actions: {                      // built-in row / tree action texts
        add: 'Add row',
        delete: 'Delete row',
        duplicate: 'Duplicate row',
        moveUp: 'Move up',
        moveDown: 'Move down',
        expand: 'Expand',
        collapse: 'Collapse',
        expandAll: 'Expand all',
        collapseAll: 'Collapse all'
      },
      contextMenu: {                  // header menu built-ins
        sortAsc: 'Sort Ascending',
        sortDesc: 'Sort Descending',
        clearSort: 'Clear Sort',
        hideColumn: 'Hide Column',
        freezeColumn: 'Freeze Column',
        unfreezeColumn: 'Unfreeze Column',
        columnVisibility: 'Column Visibility',
        showAll: 'Show all'
      }
    }

labels.inlineActionsHeader is the inline actions column header
(toolbarPosition 'inline'); '' gives a blank header.


CSS VARIABLES
-------------
Key CSS variables for styling toolbar and context menu:

Toolbar:
    --wg-toolbar-btn-min-width    min-width for toolbar buttons
    --wg-inline-actions-gap       gap between inline action buttons
    --wg-spacing-sm               used for inline actions cell padding

Context menus (cell + header) — core openMenu() in the grid's shadow root.
One public set on web-grid, UNSET by default; each resolves
--wg-context-menu-X (this grid) -> --km-menu-X (page-wide, :root)
-> --base-* -> core default:
    --wg-context-menu-bg              menu background
    --wg-context-menu-bg-hover        item hover / focus background
    --wg-context-menu-hover-color     item text color on hover (default unchanged)
    --wg-context-menu-text-color      text color
    --wg-context-menu-border          menu border
    --wg-context-menu-border-radius   border radius
    --wg-context-menu-shadow          box shadow
    --wg-context-menu-min-width       menu minimum width
    --wg-context-menu-padding         menu padding
    --wg-context-menu-font-size       font size
    --wg-context-menu-item-padding    item padding
    --wg-context-menu-item-gap        gap between icon, label, shortcut
    --wg-context-menu-toggled-color   toggled-on item color
    --wg-context-menu-icon-width      icon column width
    --wg-context-menu-icon-font-size  icon font size
    --wg-context-menu-arrow-font-size submenu arrow font size
    --wg-context-menu-shortcut-color  shortcut hint color
    --wg-context-menu-danger-color    danger item text color
    --wg-context-menu-danger-bg-hover danger item hover background
    --wg-context-menu-divider-color   divider color
    --wg-context-menu-divider-margin  divider margin
    --wg-context-menu-disabled-opacity disabled item opacity
    --wg-context-menu-z-index         z-index (default 10000)

  :root { --km-menu-bg: #fafafa; }                 every KeenMate menu
  web-grid.orders { --wg-context-menu-bg: #eef; }  just this grid's menus

Menu markup: .km-menu (.km-menu--submenu) > .km-menu__item
(--disabled / --danger / --toggled / --has-submenu), __icon, __label,
__shortcut, __divider. Cell menu levels also carry .wg-context-menu, header
menu levels .wg-header-menu. Toggle items (isToggled / getIsToggledCallback;
column-visibility toggles, class wg-header-menu__column-toggle) are
role="menuitemcheckbox" + aria-checked.

Menu keyboard: Shift+F10 / ContextMenu key on the focused cell opens the cell
menu below it (first item focused). Up / Down (disabled skipped), Home / End,
Right / Enter / Space open a submenu, Left / Escape close it, Enter / Space
activate, Escape closes and returns focus to the cell, Tab closes, an item's
shortcut letter activates it.
