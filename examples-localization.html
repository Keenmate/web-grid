LO01 · Instance labels

Every text the grid shows has a flat key <elementType>.<name> (labels.perPage, messages.noData, menuItems.deleteRow, …). labels on ONE element overrides keys for that grid only — a short key (labels.perPage) or the full key (web-grid.labels.itemCount), as a property or the JSON attribute labels='{…}'. Keys you don't set keep the page-wide text, then the English default. 


        
grid.labels = {
  'labels.perPage': 'rows per page',              // short key
  'web-grid.labels.itemCount': '{count} records'  // full key — same effect
}
// or in HTML: <web-grid labels='{"labels.perPage":"rows per page"}'>
grid.labels = null   // back to page-wide / English

    


    

        
LO02 · Page-wide dictionary

        

            An app loads ONE flat translation JSON and hands it to window.components.locale.labels; the keys are
            the full web-grid.<elementType>.<name> keys, so the same dictionary can hold every
            component's (and the app's own) texts. It translates every grid on the page at once — both grids below, and
            the grids in the other sections too. Assigning replaces the page object and re-renders every live component.
        

        

            
            window.components.locale = null
        

        

            
            
        

        

        
const cs = await (await fetch('/i18n/cs.json')).json()
// cs.json:
// {
//   "web-grid.labels.pageInfo": "Strana {current} z {total}",
//   "web-grid.labels.itemCount": "{count} položek",
//   "web-grid.labels.perPage": "na stránku",
//   "web-grid.messages.noData": "Žádné položky",
//   "web-grid.menuItems.sortAsc": "Seřadit vzestupně",
//   "web-grid.menuItems.sortDesc": "Seřadit sestupně",
//   "web-grid.menuItems.clearSort": "Zrušit řazení",
//   "web-grid.menuItems.hideColumn": "Skrýt sloupec"
// }
window.components.locale = { labels: cs }
window.components.locale = null   // back to English

    


    

        
LO03 · translateCallback

        

            An app with its own i18n library plugs it in as translateCallback({ component, key, template, params, locale }):
            it gets the full key and returns the text, or null for "not mine". The grid's OWN
            translateCallback is asked first; its null passes the key on to the page-wide
            window.components.locale.translateCallback, then the dictionary / English. A key the instance
            labels set is never sent to either callback — the instance text wins. Below: a tiny
            i18next-like lookup (no real i18next). The grid's own callback knows German labels.pageInfo only; the page
            one knows Czech; this grid's labels sets labels.perPage.
            The page-wide callback is page-wide: the other grids follow it too.
        

        

            
            
        

        
        

        
// an i18next-like lookup: resources + t(key, params) with {{name}} interpolation
const i18n = {
  resources: {
    cs: { 'web-grid.labels.pageInfo': 'Strana {{current}} z {{total}}', 'web-grid.labels.itemCount': '{{count}} položek', 'web-grid.labels.perPage': 'na stránku' },
    de: { 'web-grid.labels.pageInfo': 'Seite {{current}} von {{total}}' }
  },
  exists: (lng, key) => key in i18n.resources[lng],
  t: (lng, key, params) => i18n.resources[lng][key].replace(/\{\{(\w+)\}\}/g, (_, name) => params?.[name] ?? '')
}
// this grid only — asked first; null = not mine
grid.translateCallback = ({ key, params }) => (i18n.exists('de', key) ? i18n.t('de', key, params) : null)
// every component on the page
window.components.locale = {
  translateCallback: ({ key, params }) => (i18n.exists('cs', key) ? i18n.t('cs', key, params) : null)
}
grid.labels = { 'labels.perPage': '/ page (instance labels)' }   // never sent to a callback

    


    

        
LO04 · Screen-reader name / tooltip follow

        

            The pager buttons show glyphs (buttons.firstPage = ⏮) and name themselves through
            ariaLabels.firstPage ("First page"). Translate only the visible caption and the
            ariaLabels.x / tooltips.x nobody set follows it — a page that translates what it
            sees never leaves an English screen-reader name behind. An ariaLabels.x you set yourself wins.
            The accessible names below are read from the buttons' aria-label in the shadow root.
        

        

            
            
        

        
        
pager buttons: text → accessible name

        
grid.labels = {
  'buttons.firstPage': '« První',
  'buttons.previousPage': '‹ Předchozí',
  'buttons.nextPage': 'Další ›',
  'buttons.lastPage': 'Poslední »'
  // ariaLabels.firstPage … nobody set → they follow: aria-label="« První", …
}
grid.labels = { ...grid.labels, 'ariaLabels.nextPage': 'Přejít na další stránku' }   // set = wins
button.getAttribute('aria-label')   // read from the shadow root's pager buttons

    


    

        
LO05 · locale + formatting

        

            web-grid has no locale input of its own — it follows the page locale
            (window.components.locale.locale), else the browser. What follows it: number values inside labels
            (the pager's {count}: "1,234 items" / "1 234 items") and the date editor's month / weekday names
            (double-click a Due (editor) cell). What does NOT: cell values. A number cell shows the raw value
            (String(value)), a date column shows its editorOptions.dateFormat pattern
            (DD.MM.YYYY here, in every locale). For locale-formatted cells, format them yourself in
            getDisplayValueCallback with the resolved locale (the (Intl) columns).
        

        
page locale
            
            
            
            
        

        
        

        
import { resolveLocale } from '@keenmate/web-components-core/locale'

grid.isEditingEnabled = true
window.components.locale = { locale: 'cs-CZ' }   // pager count "1 234 items", Czech calendar
grid.columns = [
  { field: 'amount', title: 'Amount (raw)' },                                     // 1234567.891 — as is
  { field: 'amount', title: 'Amount (Intl)',
    getDisplayValueCallback: ({ value }) => new Intl.NumberFormat(resolveLocale()).format(value) },
  { field: 'due', title: 'Due (editor)', isEditable: true, editor: 'date', editorOptions: { dateFormat: 'DD.MM.YYYY' } },
  { field: 'due', title: 'Due (Intl)',
    getDisplayValueCallback: ({ value }) => new Intl.DateTimeFormat(resolveLocale(), { dateStyle: 'medium' }).format(new Date(value)) }
]

    


    

        
LO06 · shouldEscapeLabels

        

            Below, both labels carry markup: messages.noData = Nothing <b>here</b> yet
            and labels.pageInfo = Page <b>{current}</b> of {total}.
            The rule (core /locale): a label's template may be markup, its {name} values are DATA and are
            escaped (a user name like <i>Ann</i> shows its tags as text);
            window.components.security.shouldEscapeLabels escapes the whole label. What web-grid does today: it
            reads every label as text (.text(), never .html()), so the switch changes nothing here.
            The empty-table message is escaped — the <b> shows as typed. The pager texts
            (labels.pageInfo, labels.itemCount, buttons.*Page) are written as markup,
            so the <b> renders bold in both states. The readout shows the rendered HTML.
        

        

            
            window.components.security = undefined
        

        

            
            
        

        

        
grid.labels = {
  'messages.noData': 'Nothing <b>here</b> yet',          // empty-table cell: escaped
  'labels.pageInfo': 'Page <b>{current}</b> of {total}'    // pager: written as markup
}
window.components.security = { shouldEscapeLabels: true }   // affects .html() labels — web-grid uses none
