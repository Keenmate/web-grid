🌲 Tree / Hierarchy

Render hierarchical data using an ltree-style path string. Mark one column with isTree: true to add depth-based indentation and an expand/collapse chevron.

Organizations

Each row carries a path like "1.2.3". Levels and parent paths are derived automatically; provide treeLevelMember / treeParentMember if your DB already computes them.

Sorting in tree mode is sibling-aware: clicking a header sorts each parent's children among themselves (e.g., "sort each department's sub-teams by Annual Budget"). The hierarchy stays intact — parents always appear above their children.

For custom sort logic (e.g., sort departments by total budget aggregated over all descendants), set treeDataSorted: true, listen to ondatarequest, sort the items yourself, and push them back via grid.items = …. The grid will trust your order completely and skip its internal sibling sort.

Keyboard: click a cell, then arrows move focus, Ctrl/Cmd + ← collapses the focused parent (or walks up to the nearest expanded ancestor), Ctrl/Cmd + → expands. Right-click for tree context-menu items. (This grid is in editTrigger: 'navigate'.)

Expanded paths: —

Right-click any row for the context menu — the tree-specific predefined items (Expand all, Collapse all, Expand entire tree, Collapse entire tree) appear automatically. Expand all/Collapse all only show on rows that have children.

Keyboard Navigation + Heterogeneous Tree

This grid uses editTrigger: 'navigate' — cells are focusable, arrow keys move the focus, and editing starts on Enter / F2 / typing. Click any cell to focus it, then try:

  • Ctrl/Cmd + ←: collapse the focused parent row, or walk up to the nearest expanded ancestor and collapse that (refocuses the ancestor).
  • Ctrl/Cmd + →: expand the focused row when it has children and is collapsed.
  • Tab / Shift-Tab: jumps to the next/previous editable cell. In this grid only leaf rows are editable — Tab skips Acme / Engineering / Platform Team and walks straight from leaf to leaf. The tree column itself is always read-only (since v1.2.0), so Tab skips it too.
  • Right-click any row: tree context-menu items ('expand-all', 'collapse-all', 'expand-tree', 'collapse-tree') plus a custom "Show row data" action. The first two only show on parent rows.
// Heterogeneous tree: only leaf rows are editable
const isLeafRow = row => !parentPaths.has(row.path)

navGrid.editTrigger = 'navigate'
navGrid.isEditable = true
navGrid.columns = [
    { field: 'name', title: 'Organization', isTree: true },     // tree column — always read-only
    { field: 'headcount', title: 'Headcount', isEditable: isLeafRow, editor: 'number' },
    { field: 'budget',    title: 'Annual Budget', isEditable: isLeafRow, editor: 'number' },
    { field: 'location',  title: 'Location', isEditable: isLeafRow },
    { field: 'status',    title: 'Status' }                     // never editable
]

navGrid.contextMenu = [
    'expand-all', 'collapse-all',
    { dividerBefore: true },
    'expand-tree', 'collapse-tree',
    { dividerBefore: true,
      label: 'Show row data',
      icon: 'ℹ',
      onclick: ctx => alert(JSON.stringify(ctx.row, null, 2)) }
]

Row-Level Editability with isRowEditable

Same Tab-skips-read-only-rows behaviour as the previous card, but expressed differently. Instead of a per-column isEditable: predicate on every column, this grid uses isRowEditable at the grid level — one function decides whether the whole row is editable. Useful when the same condition applies across all columns.

Here the rule is non-tree-related: only rows with status "Active" are editable. Channel (Reorganizing) and IT (Frozen) are read-only even though they're leaves; parent rows like Acme / Engineering remain editable. Tab walks past Channel and IT and lands on the next Active row.

// Grid-level row gate — applies to every column on every row
rowGateGrid.editTrigger = 'navigate'
rowGateGrid.isEditable = true
rowGateGrid.isRowEditable = row => row.status === 'Active'

rowGateGrid.columns = [
    { field: 'name', title: 'Organization', isTree: true },     // tree column — always read-only
    { field: 'headcount', title: 'Headcount', editor: 'number' },
    { field: 'budget',    title: 'Annual Budget', editor: 'number' },
    { field: 'location',  title: 'Location' },
    { field: 'status',    title: 'Status' }
]

When to use which: per-column isEditable: predicate when different columns need different rules; grid-level isRowEditable when the rule is uniform. The two compose — a row must pass both gates to be editable.

Column Visibility (Tree mode)

Toggle column visibility while in tree mode — same isHidden + headerContextMenu wiring as a flat grid. The interesting case: hide the tree column itself and see what happens (the chevrons go with it).

Yellow border = tree column (locked — always visible in tree mode). You can also right-click any header for the context menu (Hide Column / Column Visibility).

What to look for:
  • Hiding non-tree columns: the tree column behaves normally, indent + chevron unchanged.
  • The tree column cannot be hidden in tree mode: it's omitted from both the predefined Column Visibility submenu and the manual toggle list above. Right-clicking the tree column header also hides the Hide column action. The grid would have no way to render hierarchy depth without it.
  • Toggling expand/collapse via double-click on a non-tree column? It shouldn't work — treeDoubleClickBehavior only fires on the tree column.

Custom Sort: Grouped Aggregate

When you want to sort siblings by an aggregate over their descendants (e.g. "sort departments by total budget across all sub-teams"), set treeDataSorted: true and own the order yourself. The grid will fire ondatarequest when sort changes, you compute the aggregate, sort, and push items back. The grid never re-sorts internally in this mode.

Try it: Click Headcount or Annual Budget. Acme's sub-orgs reorder by their total headcount/budget — Engineering rises because its subtree is the largest. Without aggregation (the first grid above), the same click would only reorder by each row's own value.

How it works

aggGrid.treeDataSorted = true              // grid won't re-sort
aggGrid.expandedPaths = new Set(allPaths)  // own expansion too, so re-setting items keeps it stable

aggGrid.ondatarequest = ({ sort }) => {
    if (!sort.length) {
        aggGrid.items = [...originalData]
        return
    }
    const { column, direction } = sort[0]
    const sign = direction === 'asc' ? 1 : -1

    // Build path → row and parent → children maps
    const byPath = new Map(originalData.map(r => [r.path, r]))
    const childrenOf = new Map()
    const roots = []
    for (const r of originalData) {
        const idx = r.path.lastIndexOf('.')
        const parent = idx >= 0 ? r.path.slice(0, idx) : null
        if (parent && byPath.has(parent)) {
            (childrenOf.get(parent) ?? childrenOf.set(parent, []).get(parent)).push(r.path)
        } else {
            roots.push(r.path)
        }
    }

    // Compute aggregate (self + all descendants) for the sort column
    const agg = new Map()
    const compute = (p) => {
        if (agg.has(p)) return agg.get(p)
        let sum = byPath.get(p)[column] ?? 0
        for (const kid of childrenOf.get(p) ?? []) sum += compute(kid)
        agg.set(p, sum); return sum
    }
    roots.forEach(compute)

    // Walk depth-first, sort siblings by aggregate
    const result = []
    const walk = (paths) => {
        ;[...paths].sort((a, b) => sign * (agg.get(a) - agg.get(b))).forEach(p => {
            result.push(byPath.get(p))
            walk(childrenOf.get(p) ?? [])
        })
    }
    walk(roots)

    aggGrid.items = result
}

Other Path Formats + Custom Chevron Icons

The grid auto-detects the separator — the same data shape works with / (filesystem) or \ (Windows) paths. This grid also swaps the default ▼ / ▶ glyphs for Font Awesome icons via treeChevronCallback.

How the Font Awesome icons are wired up

  1. Add the Font Awesome stylesheet to the page <head> — once it's loaded, the @font-face is registered globally and reachable from inside the grid's shadow DOM.
  2. Class definitions (.fa-folder::before { content: '\f07b' } etc.) live in the document and don't pierce the shadow DOM — re-declare just the ones you use via customStylesCallback.
  3. Return the icon HTML from treeChevronCallback({ expanded, hasChildren, row, level, path }). Result is cached per (row, expanded, hasChildren), so the callback fires at most a handful of times per row.
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fortawesome/fontawesome-free@6/css/all.min.css">

files.customStylesCallback = () => `
    .fa-solid { font-family: 'Font Awesome 6 Free'; font-weight: 900; }
    .fa-folder::before      { content: '\f07b'; }
    .fa-folder-open::before { content: '\f07c'; }
    .fa-file::before        { content: '\f15b'; }
    .fa-folder, .fa-folder-open { color: #f4c430; }
`

files.treeChevronCallback = ({ expanded, hasChildren }) => {
    if (!hasChildren) return '<i class="fa-solid fa-file"></i>'
    return expanded
        ? '<i class="fa-solid fa-folder-open"></i>'
        : '<i class="fa-solid fa-folder"></i>'
}
